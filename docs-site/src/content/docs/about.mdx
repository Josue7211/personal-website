These docs are not a dump of every repo. They are the working manual for systems that are either maintained, operational, or important enough that future-me needs the details.

## Inclusion rule

A project gets a page when at least one of these is true:

- It has a runbook someone can follow.
- It has architecture worth explaining.
- It is used across multiple projects or machines.
- It has security, deployment, or operational risk.
- It is a flagship project where the design decisions matter.

## Exclusion rule

A project stays out when the only available content is "I built this" or "this is planned." Thin docs make the site look bigger but less useful.

Unfinished client work, early product drafts, old experiments, and hardware projects without finished evidence should not be listed here yet.

## Page shape

Each project page should answer four questions:

1. What problem does it solve?
2. What is the actual operating model?
3. What are the boundaries and risks?
4. What should be documented next?

That keeps pages closer to docs and farther from portfolio copy.
