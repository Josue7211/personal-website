These docs are for projects with real operating surface: tools I run, systems I maintain, and workflows that need instructions later.

## Published scope

The docs are intentionally narrower than the project list on the main portfolio. A repo earns a docs page when there is something useful to explain beyond a one-line project card.

| Area | What belongs here |
| --- | --- |
| Agent stack | Multi-page docs for the main agent products: memory, secrets, shell/runtime, and claw control. |
| Claude Code skills | Reusable skills and automation I run across coding sessions. |
| Homelab | Network topology, tunnels, internal tools, security boundaries, and deployment notes. |

## Start here

- [memd](/agent-stack/memd/overview/) documents the memory layer that keeps agent sessions from losing project truth.
- [claw control](/agent-stack/claw-control/overview/) documents the control surface for supervising agent work.
- [security-sweep](/claude-code-skills/security-sweep/) documents the repeatable security review workflow.
- [Homelab topology](/homelab/topology/) explains where public traffic, private services, and local machines meet.
- [How this site is deployed](/homelab/deployment/) covers the static docs deploy path through the services VM.

## What stays out

Unfinished or thin projects stay off this docs site until there is a stable implementation, runbook, or case study worth maintaining.

That is deliberate. The portfolio can still mention experiments; the docs should stay useful.
